# TIMCHENKO PLATFORM — чек-лист переноса на существующий сайт

Рекомендуемая модель: публичный сайт `timchenko.pro` остаётся маркетинговым, а платформа открывается в защищённом разделе `/platform`. В шапке сайта появляется кнопка «Личный кабинет».

## 1. Решения перед разработкой

- [ ] Подтвердить адрес первого раздела: `/platform`.
- [ ] Подтвердить первый набор ролей: владелец/администратор, менеджер, инженер, клиент.
- [ ] Выбрать способ входа: Telegram, email/код или оба варианта.
- [ ] Выбрать первый production-объект для заполнения и демонстрации.
- [ ] Зафиксировать, какие данные клиент видит, а какие остаются только команде.

## 2. API в существующем backend

- [ ] Расширить существующий `platform-api`; не создавать второй backend.
- [ ] Добавить `object.tree` для `zones -> systems -> nodes`.
- [ ] Добавить CRUD зон, систем и узлов с проверкой роли.
- [ ] Добавить список/CRUD работ и связь работ с существующими задачами.
- [ ] Добавить план материалов с поиском по `catalog_products_v2`.
- [ ] Добавить создание закупки из `project_materials` или существующей сметы.
- [ ] Добавить клиентский read-only payload объекта.
- [ ] Добавить журналирование изменений в существующий `activity_log`/`channel_events`.

## 3. Интерфейс `/platform`

- [ ] Экран выбора объекта.
- [ ] Главная объекта: этап, прогресс, ближайшие задачи, бюджет и события.
- [ ] Экран «Структура»: зоны, системы и узлы.
- [ ] Экран «Работы»: список, статусы, ответственные и сроки.
- [ ] Экран «Материалы и закупки».
- [ ] Экран «Фото и документы» на существующих таблицах.
- [ ] Клиентский режим без административных действий.
- [ ] Адаптация под телефон и Telegram WebView.

## 4. Безопасность

- [ ] Не помещать `service_role` или секреты в браузерный bundle.
- [ ] Все записи выполнять через существующий API или authenticated RPC с проверкой пользователя.
- [ ] Проверить каждое действие для разных организаций и проектов.
- [ ] Проверить истёкшую/отозванную сессию и прямой вызов API без интерфейса.
- [ ] Повторно запустить Supabase security/performance advisors.

## 5. Начальное заполнение

- [ ] Создать клиента и связать его с существующим `app_user` при наличии.
- [ ] Создать зоны первого объекта.
- [ ] Создать инженерные системы и узлы.
- [ ] Связать существующие задачи, медиа и документы через новые nullable FK.
- [ ] Перенести материалы утверждённой сметы в `project_materials` без изменения старой сметы.
- [ ] Сверить totals, статусы и доступ клиента до публикации.

## 6. Проверка и запуск

- [ ] Unit/contract tests для API.
- [ ] Проверка полного пути: вход -> объект -> система -> работа -> материал -> закупка.
- [ ] Проверка Telegram Bot, Mini App и Client Cabinet после изменений.
- [ ] Проверка desktop/mobile и Telegram WebView.
- [ ] Мягкий запуск только для администратора и одного тестового объекта.
- [ ] Подключение клиента после приёмки командой.
- [ ] План отката UI/API без отката additive-схемы.
